# OSTF Studio development handoff

Read this file after `AGENTS.md` when resuming work on another computer. Update it in the same change as significant implementations, fixes, or validation results. Record what changed, what was verified on each platform, and what remains to be done. Keep durable policy in `AGENTS.md` and detailed procedures in the linked documents.

## Current state

- `feature/track-level-meters` adds stereo sample-peak meters to track headers and all mixer strips, including buses, returns, Master and Cue. Drag the bottom edge of a source or output row to resize it. Double-click to fold or restore it. Expanded note rows show pitch and duration on the clip timeline. Row heights belong to the open view and reset when opening a song.
- The Windows x64 Release configuration passed 12 CTests. `ostf_studio_track_view` exercises hit-testing, drag resizing, folding, scrolling and meter/clip drawing. `ostf_studio_stock_effects` compares post-insert/fader master and Cue meter readings with rendered samples and checks the bus, return, pan and mute paths. The local package output directory is `dist/windows-track-meters/`. macOS arm64 and listening through a physical audio device remain to be verified for this change.

- On `feature/studio-effects-demos`, each stock effect is an independent OSTF Studio stereo VST3. The five demos include a GM instrument per source track, ordered inserts, two mix buses, post-fader sends to a wet reverb, and a master limiter. For a quick audition, solo the opening piano in Blue Hour Waltz and alternate muting Bus B and Return 1. See [the demo gallery and verification procedure](examples/demo-songs/README.md).
- The stock device catalog supplies stable VST3 class IDs to the production reader/writer and generator. Keep the class codes stable when changing plug-ins. The pinned Score, Production Session and Manifest schemas, reference package validator and routing checks passed for all five demo pairs. Offset Bridges remains a mixed-meter interchange fixture. New installers are development builds until an explicit release.
- The Windows x64 Release build passed 11 CTests, including stock VST3 discovery, audio processing, state recall, and an offline render of the Blue Hour Waltz piano through its authored bus and reverb return. Inno Setup produced the installer. The extracted Portable ZIP passed the same stock audio test with all nine effect bundles and their notices. Test the real device output and interactive mixer separately. The macOS arm64 build and installer have not been run for this branch.

- The `feature/smf-language-toolbar` branch adds File → Save as MIDI (SMF) for merged format 0 and multitrack format 1. It exports the current score, including recorded or inserted clips, and uses explicit event channels or the current track channel. The visual chord-voicing projection is excluded from source-track export. Song MIDI readback and language fallback checks run in CTest.
- Settings → Language stores `system`, `en` or `ja` in the local view preferences. The UI chooses its catalog before creating the splash screen. A new launch applies the preference. Maintain Japanese Studio strings in `assets/Japanese.txt`. External plug-in editors supply their own language. The icon toolbar shares commands and visibility state with View. English and Japanese READMEs link to each other and to the published installers.
- Local Windows x64 Release passed all 10 CTests. Windows x64 and macOS arm64 CI both built, tested and packaged the SMF and language changes at `ec0e406`. Interactive menu testing and physical audio-device checks remain open. [Cross-platform validation](https://github.com/yoh-nak/OSTF-Studio/actions/runs/45060796272)

- The release target is `v1.0.0-alpha.2` for Windows x64 and macOS arm64. The two READMEs link to the public installer assets. See [the alpha 2 release notes](docs/releases/v1.0.0-alpha.2.md), [release procedure](docs/RELEASING.md) and [publication history](https://github.com/yoh-nak/OSTF-Studio/releases).
- This alpha uses GPL-3.0-only for original app and plug-in code. Windows enables WASAPI and the ASIO SDK's GPLv3 option. JUCE uses its AGPLv3 option. Binary packages carry licenses and releases include the matching source archive. Physical ASIO and Core Audio playback still require separate verification.

- The GM VST3 uses a sixteen-part editor with standard program names, MIDI activity and saved controls. Deployment builds package the checksum-pinned FluidR3 GM bank with its license notice. See README for development provisioning.
- Demo scores now use varied chord lengths. The arrangement and piano roll have independent horizontal zoom and scroll controls. Demo files use regular Production Session instrument devices with VST3 class IDs. OSTF Core track MIDI channels and Program Change events select the GM programs. Standalone scores use the common Studio production settings. The original preview SF2 built into the VST3 uses four pitch zones and band-limited harmonic samples. A user SoundFont can still be loaded. Mixed meter, vocal synthesis and physical audio verification remain pending.
- Global note rows share the normal mixer and piano roll. Chord Voicing is the sole global voicing row, derived from Core harmony snapshots. Its mixer settings are stored in the Studio extension. Performed parts with the `voicing` role stay in Arrangement Tracks. Lead, melody and vocal roles continue to display in the global note rows. Core score tracks and voicing snapshots retain their original representation.
- The five demo songs now run approximately 2:22 to 3:00 with seven or eight tracks. Paper Lantern Replies aligns all lead and backing vocals to original lyrics and contains per-section vocal expression, pitch, technique and breath data. The preview displays the supported lanes and requires a separate sound source for playback; vocal synthesis is pending.
- OSTF Arranger uses the normal track Instrument slot. Inside its editor, the manufacturer menu reads the Studio VST3 cache and offers direct file browsing. The MIDI drag creates a MIDI clip for another DAW. The Studio editor wrapper has a separately labeled native note drag.
- The Piano Roll toolbar places **Drag MIDI to another DAW** at its right edge. Source and output FX buttons open an ordered panel with drag handles and direct Up and Down controls.
- The original demo gallery now uses voiced inversions and distinct sectional arrangements. File → Demo songs bundles the four supported songs. Offset Bridges remains a mixed-meter fixture on disk. Paper Lantern Replies covers lyric alignment, MIDI expression, five normalized vocal curves, pitch, breath and technique metadata. See examples/demo-songs/README.md for display and playback coverage.
- The Track menu adds pitched, drum/percussion or audio tracks and deletes selected tracks with confirmation. The edit keeps surviving track settings and WAV links. Windows test coverage includes track edits, FX order and output mute persistence. The edited score passed Core Schema validation. Drum-grid editing, drum recording and macOS remain pending.
- The Plug-in Browser lists the bundled VST3 as **OSTF Studio → OSTF Arranger** when it finds the bundle in an install or portable location, independently of the scan cache. Drag it onto a source track and use its editor to load a VST3 instrument. The editor provides separate OSTF and MIDI drag controls when hosted by Studio. External DAWs get the MIDI drag control.
- Master, buses and returns have synchronized volume and mute controls in the arrangement and Mixer. Source and output tracks support ordered chains of up to eight stereo VST3 effects, managed from FX or added by dropping onto a track. Both save formats preserve assignments and order. Plug-in state, automation, latency compensation and external effects testing remain pending.
- OSTF and OSTFP restore the supported mixer, MIDI routing and output insert assignments. OSTF stores these settings in a Studio extension and copies linked WAVs into a sibling `<song>.media` directory. OSTFP bundles the linked WAVs and a hash-linked Production Session 0.3 document. Instrument assignments, internal plug-in state and hardware settings are outside this save subset.
- `.ostf` and `.ostfp` have distinct document and package icon resources for Windows and macOS.
- The Windows read/write regression reopens both formats, checks added notes and mixer settings, and compares the bytes of an unchanged score. The saved example passed the pinned Core, OSTFP manifest and Production Session schemas and both SHA-256 pins. Explorer/Finder icon rendering and the native save dialog remain unverified.

- **OSTF Arranger** is the supported arrangement plug-in in Studio and external DAWs. It hosts one user-selected VST3 instrument, renders the fixed pattern according to host transport and can restore the instrument's state. The standalone MIDI Generator and its track slot have been retired from the browser and packages.
- Arrangement tracks have a horizontal volume control and their own **Mix** popover for volume, stereo pan, bus output and return level. These share mixer state. The track reports the current instrument preset when it is provided by the plug-in.
- Arrangement clips show note counts. The piano roll displays authored velocity, CC, channel/key pressure and the vocal pitch/expression curves present in Core clips. **Paper Lantern Replies** exercises these lanes. Rendering singing expression and editing performance lanes remain pending.
- Windows x64 passed the five CTest checks, including a hosted VST3 state restore and audio render through Arranger with the GM test instrument. All five demo archives passed the pinned score and manifest Schema plus payload identity checks. UI interaction, commercial instruments, external DAWs and macOS remain unverified.
- Windows Setup registers the OSTF Studio icon and open command for `.ostf` and `.ostfp` per user. It preserves existing defaults and removes its own registrations at uninstall. The app accepts document paths at launch and through the macOS document-open callback. The macOS bundle declares both extensions through JUCE.

- Studio playback sends arrangement notes to a loaded VST3 instrument. OSTF Arranger instead produces audio from its internal pattern and hosted instrument. A track can also send on a selected channel to an instrument on another track. Each instance renders once and returns its main mono/stereo output to its owner track. Per-part mixing, effect chains, multi-output routing and project persistence remain pending.
- **OSTF GM Sound Module** is a separate VST3 with 16 MIDI channels and channel 10 percussion. It loads a local GM-compatible SF2 and is packaged with its pinned MIT-licensed TinySoundFont engine. SoundFont libraries are supplied by users.
- Windows x64 passed a VST3 render test using a one-preset SoundFont. The test checks that two configured MIDI channels render and that an unavailable program and missing percussion bank stay silent. Full-bank audition, external instruments, external DAWs and macOS playback remain unverified.

## Resume on another computer

1. Install the platform prerequisites and clone the repository using your own GitHub login if prompted. Open the clone in Codex and read [AGENTS.md](AGENTS.md), this handoff, and the [build instructions](README.md#build-core-tests-no-juce-download-needed).
2. Run `git fetch origin`, `git status --short --branch`, and `git branch -avv`. Continue from the verified remote feature branch if it exists. After the approved branch is pushed, a fresh clone can use `git switch --track origin/feature/release-packaging`. Otherwise the clone has only the changes already published to GitHub.
3. Build in a fresh local build directory. Git carries source and project documentation. Compilers, SDKs, credentials, plugins, personal settings and generated packages are managed separately on each machine.
4. Run the build and tests relevant to the next change, update this handoff, and commit on the feature branch. The pending CI check for this branch must use the artifacts-only workflow option. Follow [release and packaging procedures](docs/RELEASING.md) for packaging and approvals.
