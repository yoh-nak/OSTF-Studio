# OSTF Arranger のフレーズ編集とトラック連携

設計案。対象は、内側にVST3音源を1台ロードするアレンジャー。実装済みのプレビューは固定の C–E–G–E を試聴・MIDI出力し、Studioへのドロップ時にはStudioが同じ4音を生成する。以下はこの仕組みを置き換えるための仕様である。

## コード進行からアレンジを始める

1. 新規曲では、Composerまたは開いているアレンジャーの共通コード機能で対象範囲の進行を作り、試聴する。複数のパートで使うと決めた進行は、Studioのグローバルコードレーンの空き範囲に置く。既存の進行に重ねた場合は「コード変更を比較」を開く。既にOSTFに使いたい進行がある場合はそのまま次へ進む。
2. コードレーンまたは小節ルーラーで範囲を選ぶ。開いている対応アレンジャーで「選択範囲を取り込む」と、譜面と同じ拍位置で進行を受け取る。ノートが一つもない新規曲でも、この範囲からベースや伴奏を生成できる。既存の演奏クリップを選んだ場合は、その演奏と同時に、その区間に重なるグローバルコードを自動で取り込む。
3. たとえば4/4の2小節で、1小節目は Dm7 を4拍、2小節目は G7 を2拍、Cmaj7 を2拍とする。ベース用と鍵盤用のアレンジャーが同じ範囲を取り込み、ベースはコードの低音、鍵盤は指定されたボイシングを使って各パートを試聴する。採用する演奏をそれぞれのトラックへ置く。コードは曲に一度だけ配置すればよい。

コード進行を出力する能力と、その進行を読んで演奏を出力する能力は独立に扱う。Studioは受け取るデータの種類に合わせてコードレーンまたは演奏トラックへの配置を受け付ける。ツールを追加・廃止しても、配置済みの進行は曲のグローバルコードとして他のアレンジャーから利用できる。編集中にStudioで進行が変わった場合は、取り込んだ版で試聴を続け、「進行を再取得」してから再生成するかをユーザーが決める。

## Studio本画面でのコード変更

本画面のコードレーンは曲で採用中の進行を示し、通常の再生は保存された演奏ノートを使う。プラグイン内での採用はそのインスタンスの試聴・書き出しに効く。曲のコードを変更する操作はStudioが担当する。

| 場面 | 本画面と再生 |
|---|---|
| 曲を開く | 保存された進行とクリップをそのまま表示・再生する。生成情報が既に古い、または未検証と分かる場合だけ詳細で示す。読込を契機に曲を変更したり、全トラックに確認を求めたりしない。 |
| プラグインが進行を生成・試聴する | 本画面では現在の曲を保つ。ユーザーが案を既存コード上にドロップしたときに「コード変更を比較」を開く。別の空き位置への配置も選べる。 |
| 比較する | コードレーンの直下に一時的な「変更案」を同じ拍目盛りで表示する。変わる範囲、元と案のコード、影響を確認できたクリップを示す。元の演奏のまま和声だけを替える場合と、選んだパートも替える場合を同じ範囲で試聴できる。曲と同じ進行なら「変更なし」で閉じられる。 |
| 進行を採用する | 既定は「コードだけ変更」。元のノートが鳴る状態で聴ける。「選んだパートも合わせる」では対象と新旧の演奏を試聴して、コードと選んだ演奏を一度の操作で採用する。キャンセルは曲を保ち、Undoはその操作で採用した項目を一度に戻す。 |

変更区間は、コードの追加・削除、開始拍と長さ、ルート・構成音、分数ベース、ボイシングを比較して求める。音楽的な内容が等しい表記変更はラベルの変更として扱う。同じ内容でIDだけを変える必要はない。参照のあるコードを編集するときはIDを維持し、削除・分割で残る参照を解決できない案はそのまま確定できない。**比較には三つの状態を使う。** プラグインが取り込んだ進行、現在の曲、プラグイン案を照合する。比較中にも対象コードや選んだクリップが手編集された場合は、現在の内容で差分と試聴を更新し、改めて採用を求める。Studioでコードを直接編集した場合も、採用後の影響表示は同じ。

**既存クリップの扱い。** OSTF 5.0の任意項目 `relativePhrases.assignments` のコード参照、`generation.processes` の入力参照・読取範囲と出力から、変更を参照した演奏を特定する。別トラックでもその進行を参照したものが対象になる。コードだけ変更した後、該当クリップに「参照コード変更」と表示し、「そのまま使う」「新コードで別案を試聴」を選べる。再生成では保護ノートや手編集を保持し、変更先を特定できないときは別クリップとして比較する。音声・ドラムも記録された依存関係に応じて扱うが、和声変更を理由に自動で音声を移調したり打音を変更したりしない。手弾きや履歴なしのクリップは原演奏を保ち、希望したものだけ手動比較に加える。時間帯が重なるだけで「旧コードで生成」と断定しない。

仕様上の `current`／`stale`／`unverified` は任意オブジェクトの状態である。「参照コード変更」はStudioによるクリップごとの案内とし、スコアに独自の追従フラグを加えない。情報が粗くクリップ単位で特定できないときは、分かっている範囲だけを示す。「そのまま使う」は演奏を選ぶ操作であり、以前のコードで生成された履歴を新しいコードで生成したことにはしない。[OSTF 5.0 公式スキーマ](https://github.com/yoh-nak/Open-Song-Timeline-Format-5.0/blob/d8ce48ca6c873a5a24a94bcc80d847bf33135b46/schema/ostf-5.0.0.schema.json)

元の生成プラグインがなくても記録されたノートを再生できる。利用できる相対割り当てをStudioが扱える場合は、該当ノートの音高だけを合わせた案も試せる。いずれの方法も使えない場合は、原演奏の保持か、別のアレンジャーで新しいクリップを作る方法を示す。この比較・採用はStudio上でユーザーが行う編集として設計し、プラグインに曲の自動更新権限を与えない。

## Composerと各アレンジャーの共通コード機能

M4L版で共有してきたコード生成の基本部分を、VST3版ではホストから独立したC++ライブラリとして設計する。コードの範囲と拍位置、演奏からの解析、進行の生成、候補の試聴・修正・採用をComposerと各アレンジャーで共有する。各VST3に組み込むため、外部DAWでベース用プラグインだけを開いた場合も使える。Composerの主な出力はコード進行、パート用プラグインの主な出力は採用した進行に沿う演奏である。ベースの音域や鍵盤のリズムなどは各プラグインが担当する。各インスタンスの作業中の進行は独立させ、共有する演奏上の基準はユーザーがStudioに配置したグローバルコードとする。

| 選択した範囲 | コードを使ってアレンジするときの動作 |
|---|---|
| OSTFに進行がある | フレーズと一緒に取り込んだコード、ベース、指定のボイシングを使う。再解析は不要。Composerで別案を試すときはコピーを使う。 |
| 進行が一部だけある | 既存コードを固定し、空白区間だけの演奏を解析する。前後の確定コードは候補のつながりを評価するときに使う。 |
| コードがなく、演奏がある | OSTF／MIDIのノートを共通機能で解析し、拍位置付きの「解析候補」を出す。音の重なり・長さ、低音、拍上の位置から判断し、候補を元の演奏に重ねて試聴する。単音の旋律だけで複数の和声が成立する場合は候補から選ぶか、別の伴奏パートを解析に加える。 |
| ノートがない、打楽器だけ、または和声を特定できない | キーや長さなどを指定して「進行を生成」する。旋律があればそれに合う伴奏を提案できる。こうして作った進行は「作曲案」として表示する。 |

取り込んだ原音はすぐに試聴できる。「アレンジ生成」を選んだ時点でコードが未指定なら、同じ画面で解析候補または作曲案を原音と比較し、修正して採用してからパートの生成へ進む。解析候補と作曲案は作業用の表示で、採用だけでStudioの曲を書き換えることはない。他のパートにも同じ進行を使いたいときにだけコードレーンへ配置する。ファイルを取り込むだけの操作や、コードを使わないドラム生成にはこの手順を求めない。

## 4小節のベースを仕上げる操作

M4L版から引き継ぐのは、Composerと各パートで同じ和声を扱えること。VST3版ではJUCEのエディターに、上段のコード、中央の参照演奏と生成ノートを同じ拍目盛りで表示する。ベースを開いたときは音域とリズムの操作を前面に出し、既存の進行で作れる場合はすぐに試聴へ進める。コードの候補比較や修正は、同じ画面で該当コードを選ぶと開く。鍵盤用は同じコード編集を再利用し、固有の操作にはボイシングや伴奏リズムを置く。

1. 4小節分を生成してループ試聴する。終わり方だけ変えたい場合は4小節目を選び「選択範囲の別案を作る」を押す。Aは今の演奏、Bはそのコピーに変更を加えた試聴案とする。Bの準備中もAを聴ける。
2. 生成器には前後の音やコードを文脈として渡す。変更対象は選択範囲の内側に収まるノートに限定する。範囲外の音と境界をまたぐ持続音を保ち、その発音区間も考慮してフィルを作る。例えば単音ベースで3小節目から4小節目の1拍目まで伸ばした音があれば、そのリリース後にフィルを始める。
3. A/Bは同じ子音源・同じ再生位置で聴き比べる。再生中は次のループ先頭で切り替え、停止中は選んだ案を次の試聴に使う。「Bを採用」で1回の編集として反映し、UndoでAへ戻せる。試聴中の案と採用済みの案を表示し、ドラッグの対象をボタンに明記する。初版は採用済みの演奏をStudio／MIDIの両方へ書き出す。

### 再生と保存

- プラグインの各インスタンスが素材、和声、採用済みの演奏、比較中の案を持つ。エディターはこれを表示して編集する。ウィンドウを閉じても再生と作業内容を維持する。
- コード解析・部分生成はオーディオ処理の外で行う。入力や選択範囲を変えて再生成した場合、古い処理の完了で新しい案を上書きしない。再生処理は準備済みのイベント列を使い、切り替えで発音中のノートが残らないようにする。
- プロジェクトには採用済みのノートと比較中の案そのもの、参照したコード、子音源の状態を保存する。再読込時に生成をやり直す必要はない。旧版の子音源設定だけの保存データは、従来の4音とその音源で開く。音源が見つからない場合もノートの編集・ドラッグは使える。
- 最初の縦断テストは「4小節目だけを作り直す → A/B試聴 → Bを採用 → DAWで保存して開き直す → 書き出す」。1～3小節目と境界の持続音が一致し、採用した4小節目がStudioとMIDIの両方で同じ拍・音高・長さ・ベロシティになることを確認する。素早く2回生成して古い結果が後から届く場合と、比較中にエディターを閉じる場合も試す。

## 一つのフレーズを試聴して持ち出す

各インスタンスは編集用のフレーズを一つ持つ。元の演奏、参照したコード進行、編集結果を区別し、何度コード追従を試しても元の演奏から計算できるようにする。試聴、MIDIファイルの書き出し、Studioへのドラッグは、同じ確定済みフレーズを読む。ドラッグ開始時に内容を固定する。

| 操作 | OSTF Studio内 | 外部DAW内 |
|---|---|---|
| 読み込む | 開いた対応プラグインの「選択範囲を取り込む」。ファイル入力・MIDIキャプチャも利用できる | 「ファイルを開く」でOSTF／MIDIを選ぶか、「MIDIをキャプチャ」でDAWから届く演奏を収録する |
| 編集・試聴 | 元の演奏と編集結果を切り替え、内側の音源で聴く | 同じ操作。テンポや位置はホストが提供する範囲で利用する |
| 新しいクリップを置く | 「OSTFクリップをトラックへドラッグ」。ドロップ先トラックと音楽的な位置をStudioが決定する | 「MIDIクリップをDAWへドラッグ」。単体のSMFを受け取り側のMIDIトラックに置く。ドラッグ受け入れに制約があるホストには「MIDIファイルを保存」も用意する |
| 採用する | 別の場所または別トラックで新旧を聴き比べる。元演奏と入れ替えたい場合は、ユーザーがStudioの編集操作で対象を選ぶ | DAWで書き出したMIDIを配置し、元クリップとの入れ替えを行う |

プラグインは通常のスロットから開く。選択内容の読み取り、コード進行の受け渡し、演奏フレーズの受け渡しはインスタンスごとに対応を照会する。新規生成だけを行う製品は書き出しだけに対応できる。新製品の追加や既存製品の廃止に伴ってStudioのクリップメニューを変更する必要はない。通常のクリップ編集と、配置後のOSTFノートの読み込み・編集は、元のプラグインがアンインストールされても使える。専用音色の再現にはその音源が必要になる。

初期対象は、グローバルタイムラインの連続した1範囲、または音階付きクリップ内の1範囲とする。入力欄には小節・拍の範囲と、クリップを選んだ場合はトラック名を表示する。読み込むクリップと発音する音源は独立に選べる。ドラムやボーカルはデータと参照の保持を検証した段階で対応する。編集結果は子音源の有無にかかわらず取り出せる。

## フレーズを取り込む入口

プラグインには「コード進行」と「参照フレーズ」の二つの入力欄を用意する。コード進行だけを素材として「進行から生成」する操作と、既存の演奏を編集・試聴する操作を用意する。進行が空なら、取り込んだ演奏からコードを解析するか、新しい進行を作るところからアレンジを始められる。コードを持たないMIDIも演奏として編集・書き出しができる。この二つは作業画面上の区別で、OSTFのファイル形式には項目を追加しない。

| フレーズの入力 | 取り込む操作 | コード欄の初期状態 |
|---|---|---|
| Studioの選択範囲 | コードレーン／ルーラーで範囲を選ぶか、演奏クリップを選び、開いたプラグインで「選択範囲を取り込む」 | いずれも同じ範囲に有効なグローバルコードを自動で取り込む。部分投影で和声が提供されなかった場合は「未取得」、取得できた和声の空白は「未指定」 |
| OSTFファイル | どのホストでも「ファイルを開く」で `.ostf` と曲中の範囲を選ぶ。参照する演奏があればトラックも選ぶ | 範囲内のグローバルコードが自動で入る。別の曲の進行を使うときは「コード進行」欄からファイルと範囲を選ぶ |
| MIDIファイル | 同じ「ファイルを開く」で `.mid` を選ぶ。複数の演奏パートがあればトラック・チャンネルと範囲を選ぶ | 「未指定」。和音を押さえた演奏もフレーズとして保持する |
| DAWで再生するMIDI | 「MIDIをキャプチャ」を押し、目的のクリップのMIDIがプラグインに届く状態でDAWを再生・停止する | 「未指定」。別パートを和声の資料にしたいときは「コード進行」欄で改めて取り込む |

MIDIからは音高・開始位置・長さ・ベロシティとチャンネルを読み、選択範囲の先頭を基準とする拍位置にそろえる。OSTFではノートに付随する演奏情報や参照を保てる経路を使う。取り込み時に自動クオンタイズ・移調・コード判定を行わない。「未指定」は情報がないことを表し、音楽上の意図的な無和音やCメジャーを意味しない。

コードを使う機能を選んだときは、未指定の区間に対して「コードを入力」「OSTFからコードを読む」「伴奏MIDIから候補を出す」を用意する。別素材を追加するときは、フレーズの何小節目の何拍に合わせるかを指定し、すでにあるコードと重なる範囲をプレビューする。MIDIから得た候補は、ユーザーが採用した区間だけを使う。原音試聴に戻れば取り込み時の演奏を聴ける。コードのみのOSTFは「コード進行」欄に取り込める。その進行から新しいフレーズを作れるかは個々のプラグインが決める。

## コピーの取り込みと新規配置

1. 取り込み時、Studioは読み取り用の `context` の範囲をプロジェクトと開始tick以上終了tick未満で確定する。クリップを選んだ場合はトラック・クリップとその演奏も対象とする。グローバルコードはOSTFの開始位置と長さで選択範囲との重なりを求め、先頭より前から続くコードと小節途中の変更も含める。取り込み用の拍位置は重なりの開始から選択先頭を引き、長さは重なった分だけとする。分数コードのベースや指定のボイシングも保持する。参照可能な拍子・テンポ、キー／スケールも渡す。Studioの選択や再生位置を変えても作業中のコピーは変わらない。
2. Studioで元の音符の追加・移動・削除、コード変更、トラック削除を行っても、プラグインではそのまま試聴・書き出しできる。最新の素材を使いたいときは再度取り込み、別の作業コピーとして始める。曲を切り替えた場合も、現在の曲に明示的にドロップしたときだけ新しいクリップが置かれる。
3. ドロップで渡すのは確定した演奏。Studioが配置先で新しいクリップID・音符IDを発行し、コピー内の参照を張り直す。配置先の種類、範囲、参照を検証し、元音符へのリンクを持たない通常のOSTFクリップとして1回のUndoで追加する。既存クリップの上に落とした場合、初版は空いている位置または別のトラックを案内する。歌詞・表情などの参照を正しく複製できない場合は、配置前に対象を示す。
4. 例えばベースの5～8小節を取り込んでいる間にStudioで7小節目を録り直しても、その新しいテイクは残る。プラグインが4小節から2小節のフィルを生成した場合も、ユーザーが指定した空き位置に2小節を置く。元のどの2小節に対応するかをStudioが推測する必要はない。

最初にStudioのJUCEホストと同梱VST3を使い、バージョン付きの任意インターフェースを試作する。Studio内のドラッグには、ドラッグ開始時の内容を受け渡す短命のハンドルを使う。外部ホストで開いたインスタンスから別プロセスのStudioに持ち込む場合は、将来のファイル交換として自己完結した有効な `.ostf` のインポートを用意する。部分的な `context` は読み取り用で、スコアファイルとしては扱えない。

公式交換契約はスコア4.3.0と5.0.0を対象とする。初回の選択範囲取り込みは5.0.0を対象にする。汎用アレンジャー連携で使うのは読み取り用の `context`。既存データの更新提案（`editProposal`）は初版の機能に含めない。将来、特定の音符のベロシティだけを直すような用途が生じたときに別途検討する。その場合も対象ID・範囲・変更項目を明示できる操作に限り、Studioが現在の値と元の版を照合してユーザーに差分を提示する。競合時に古い提案を適用する経路は設けない。[OSTF Plugin Context Exchange 1.0 仕様](https://github.com/yoh-nak/Open-Song-Timeline-Format-5.0/blob/d8ce48ca6c873a5a24a94bcc80d847bf33135b46/docs/PLUGIN_EXCHANGE_PROTOCOL.ja.md)

## MIDIキャプチャと発音

- VST3のイベント入力を有効にし、プラグインに実際に届いたノートを記録する。最初の経路は「既存MIDIクリップをアレンジャーと同じインストゥルメントトラックから再生」。別トラックからのルーティングはホストが対応する場合に利用する。Liveではトラックの入出力とモニターで経路を作れる。[Ableton Liveのルーティング](https://www.ableton.com/en/manual/routing-and-i-o/)
- 「キャプチャ」を押し、次の再生開始から停止までを1テイクにする。長さ指定の場合は指定範囲の終端で終了する。受信時はブロック内のサンプル位置、チャンネル、イベントと利用可能なホスト位置を有界バッファに記録する。ループ折り返しとシークでテイクを分割し、停止時の未終了ノートを閉じる。容量超過は不完全なテイクとして明示する。音声処理スレッドの外で拍位置に変換し、元のタイミングとベロシティを保持する。ホストから音楽的位置を取得できないときは、手動BPMと取り込み開始を拍の原点に選べるようにする。
- 最初はノートオン／オフとベロシティ、チャンネルの往復を検証する。CC64を含むCC、ピッチベンド、アフタータッチは受信・書き出しの対応を項目ごとに示す。リアルタイム入力から歌詞は復元できない。MIDIファイルに歌詞メタイベントが入っている場合だけ、その時刻と文字列を歌詞割り当ての候補として提示する。Studio本体の現行SMF取り込みはコントローラーを省略するため、そのまま完全な往復には使えない。
- 通常はトラックのMIDIを子音源で鳴らす。キャプチャではその入力を記録しながらモニターする。「編集案を試聴」中は編集結果が子音源を鳴らす。自分が生成したノートをキャプチャ入力へ戻さない。試聴終了時はトラック再生に戻す。プラグインの保存状態には作業中のフレーズ、使用したコード、子音源設定を含める。プリセットを別の曲で開く場合も、そのフレーズのコピーから作業を始められる。

## コード進行と配置位置

Studioでは配置先の時刻に対応するグローバルコード進行がある区間でそれを参照する。クリップの先頭からの経過tickを配置先のスコアtickに変換し、小節途中のコード変更も拾う。分数コードのベース、明示されたボイシング、キー／スケールは別々に参照する。元のコードに対する音の役割を使う変換には、元と配置先の両方のコードが必要になる。片方でも未指定の区間では原音を保持する。グローバルのコードやボイシングをアレンジャーから自動更新する動作は範囲外とする。

初期値は「原音を保持」。キャプチャ時の経過音、ブルーノート、コード境界をまたぐロングトーンを保つ。「配置先のコードに追従」を選んだ場合は、伴奏の和声音を元のコードに対する役割から置き換え、音域と前後の声部移動を考慮した候補を試聴する。例えば Cmaj7 の E–G–B を Dm7 の同じ役割に合わせる候補は F–A–C。持続音は初期値で維持し、変更される音だけを強調する。別の場所へドラッグしたときは、ドロップ先の進行でプレビューを更新してから追従結果を確定する。

外部DAWでは、コード参照元を「OSTFから読み込み」「手入力」「コード用MIDIを取り込み」から選ぶ。ホストが有効な現在コードを渡す場合は、再生中の観測値として時刻とともに収録できる。将来の全曲の進行が取得できるという前提は置かない。ノートから推定したコードは候補に留め、ユーザーが確定するまで原音を使う。SMFに書き出すのは、プラグイン側で試聴した音高。外部DAW内で配置後に進行が変わった場合は、更新した進行で再生成・再ドラッグする。[Steinberg VST3 ProcessContext](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/structSteinberg_1_1Vst_1_1ProcessContext.html)

## 実装順と受け入れ条件

| 段階 | 完了を判定する操作 |
|---|---|
| コード変更の比較 | 9小節目の G7 を B♭7 にする案を比較する。履歴のあるベース、手弾き鍵盤、ドラムを用意し、「コードだけ変更」で全ノートが一致すること、ベースだけ合わせた場合はその別案だけが採用されること、Undoと保存再読込を確認する。旧進行に戻る案、同一内容の案、比較中の手編集、生成履歴や生成プラグインがない曲も試す。 |
| 共通コード機能 | Composerとベース用VST3を別々に起動し、同じ和音素材を同じ設定で解析して候補と区間が一致することを確認する。部分的なOSTF進行では既存区間を保持し、単音のEでは複数の解釈を試聴でき、打楽器だけの素材から作った進行は作曲案として表示されることを試す。ベース用VST3単体でも進行の採用からベース生成まで行えること、明示的に配置するまでStudioのコードレーンが変化しないことも確かめる。 |
| 最初の制作フロー | 演奏トラックが空の曲にツールで生成した Dm7・G7・Cmaj7 を置く。進行だけからベースと鍵盤の別々の演奏を生成し、両パートが2小節目の3拍目で Cmaj7 に変わることを確認する。続いて1小節目の途中からベースを選び直し、先頭から有効な Dm7 と後続の変更がノートと一緒に渡り、元のコードレーンに重複が増えないことを確認する。 |
| 1. 共通フレーズ | 固定4音のうち1音を変更し、子音源での試聴、SMFを読み戻したノート、Studioへ新規ドロップしたノートの音高・開始・長さ・ベロシティが一致する。子音源が見つからなくても書き出せる。 |
| 取り込みの共通条件 | 同じ4小節を、コードあり・なしのOSTF、単音のMIDIファイル、DAWからのMIDIキャプチャで読み込む。コード欄の状態にかかわらず元の音列・位置・長さを試聴・出力できる。途中の2小節だけコードがある場合はその区間だけを表示する。後から別の伴奏をコード欄に読み込んでもフレーズは保たれる。 |
| 2. Studio内のコピー | 2つのインスタンスを開き、片方だけにベースの5～8小節を取り込む。Studioで7小節目を録り直し、生成した2小節を別トラックへ置く。Undoで追加だけが戻り、録り直した音符は残ることを確認する。元トラック削除、途中のコード変更、既存クリップ上へのドロップ、生成専用プラグイン、配置後のプラグイン取り外し・保存再読込も試す。 |
| 3. 外部DAW | LiveとCubaseのWindows/macOS実機で、既存クリップを再生してキャプチャし、編集後のSMFを再配置して比較する。ループ、テンポ変更、途中停止、ホスト位置を取得できない場合を含める。 |
| 4. 和声追従 | 途中転調と小節途中のコード変更を含むフレーズを別位置へ置き、「原音を保持」と「コードに追従」を試聴比較する。元の進行と演奏が保持され、未知の区間と推定コードが区別できる。 |
