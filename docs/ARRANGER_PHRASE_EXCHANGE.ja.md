# OSTF Arranger のフレーズ編集とトラック連携

設計案。対象は、内側にVST3音源を1台ロードするアレンジャー。実装済みのプレビューは固定の C–E–G–E を試聴・MIDI出力し、Studioへのドロップ時にはStudioが同じ4音を生成する。以下はこの仕組みを置き換えるための仕様である。

## 一つのフレーズを試聴して持ち出す

各インスタンスは編集用のフレーズを一つ持つ。元の演奏、参照したコード進行、編集結果を区別し、何度コード追従を試しても元の演奏から計算できるようにする。試聴、MIDIファイルの書き出し、Studioへのドラッグは、同じ確定済みフレーズを読む。ドラッグ開始時に内容を固定する。

| 操作 | OSTF Studio内 | 外部DAW内 |
|---|---|---|
| 読み込む | クリップの右クリック「アレンジャーで編集」。対象トラックのインスタンスへ、選択クリップとその範囲の曲情報を渡す | 「MIDIファイルを開く」または「入力MIDIをキャプチャ」。DAWのクリップを再生してプラグインの入力へ送る |
| 編集・試聴 | 元の演奏と編集結果を切り替え、内側の音源で聴く | 同じ操作。テンポや位置はホストが提供する範囲で利用する |
| 新しいクリップを置く | 「OSTFクリップをトラックへドラッグ」。ドロップ先トラックと音楽的な位置をStudioが決定する | 「MIDIクリップをDAWへドラッグ」。単体のSMFを受け取り側のMIDIトラックに置く。ドラッグ受け入れに制約があるホストには「MIDIファイルを保存」も用意する |
| 元のクリップに戻す | 元トラック・クリップ・範囲を明示した「元クリップに反映」。差分を確認して1回のUndoで戻せる | DAWで書き出したMIDIを配置し、元クリップとの入れ替えを行う |

読み込むクリップと発音する音源は独立に選べる。Studioでは、別の音源が既にあるトラックのクリップも、開いているアレンジャーを選んで送れる。インスタンスが複数ある場合は曲名・トラック名で送り先を示す。初期対象は音階付きクリップ1個。ドラムの音色スロット、ボーカルの歌詞・発声参照に対応する段階でそれぞれを有効にする。編集結果は子音源の有無にかかわらず取り出せる。

## Studioとの往復

1. Studioは開いているプロジェクト、トラックID、クリップID、対象の半開区間、元スコアの版を記録する。プラグインに渡す読み取り用の `context` には、その区間の音符・演奏情報、冒頭ですでに有効なコード、その後のコード変更、キー・スケール、拍子・テンポを含める。表示名や現在選択中のトラックが変わっても編集先は固定する。
2. プラグインはクリップ先頭をゼロとする作業用時刻と元スコア上の位置を保持する。移動・長さ・音高の変更では元の音符IDを維持する。新規クリップとして置く場合は新しいIDを割り当て、コピー対象内の参照を張り直す。対応外の歌詞・表情・外部参照があるコピーや削除は、欠落をプレビューに示して対象操作を止める。元クリップへの反映では編集対象外の項目を保持する。
3. 「元クリップに反映」は公式の `editProposal` を生成する。Studioが操作の許可、選択範囲、スコアの元バイト列のSHA-256、該当する版ID、各編集先のID・パス・期待値を検証する。スコアのコピー上で全変更を適用し、スキーマと参照を検証する。元スコアや和声が変更済みなら、最新の範囲を読み直して差分を再提示できるよう編集案を保持する。他トラックへ新規配置する場合も、ドロップ先のスコアと権限で独立して検証する。
4. 画面上の反映とファイル保存の状態を表示し分ける。受領は `received`。ホストが承認された保存に成功して初めて `applied` と保存後のスコアSHAを返信する。返信先は元メッセージのID。同じ提案の再送は二重適用を防ぐ。保存時にはOSTFP内の制作セッションが参照するスコアSHAも、その保存操作で個別に検証・更新する。

連携機能はインスタンスごとに接続時に照会する。最初にStudioのJUCEホストと同梱VST3との間で、バージョン付きの任意インターフェースを試作する。読み取り、提案、ドロップ受領の能力に応じて操作を表示する。プラグイン名による分岐や、VST3モジュールとアプリ間でのC++オブジェクトの共有には依存しない。ドラッグの受け渡しにはインスタンスと生成時のフレーズを識別する短命のハンドルを使う。外部ホストで開いたインスタンスから別プロセスのStudioに持ち込む場合は、将来のファイル交換として自己完結した有効な `.ostf` のインポートを用意する。部分的な `context` をそのままスコアファイルとして保存することはできない。

公式交換契約はスコア4.3.0と5.0.0を対象とする。初回実装は5.0.0の往復に限定し、古いスコアはStudioで5.0.0のコピーを保存してからリンクする。[OSTF Plugin Context Exchange 1.0 仕様](https://github.com/yoh-nak/Open-Song-Timeline-Format-5.0/blob/d8ce48ca6c873a5a24a94bcc80d847bf33135b46/docs/PLUGIN_EXCHANGE_PROTOCOL.ja.md)

## MIDIキャプチャと発音

- VST3のイベント入力を有効にし、プラグインに実際に届いたノートを記録する。最初の経路は「既存MIDIクリップをアレンジャーと同じインストゥルメントトラックから再生」。別トラックからのルーティングはホストが対応する場合に利用する。Liveではトラックの入出力とモニターで経路を作れる。[Ableton Liveのルーティング](https://www.ableton.com/en/manual/routing-and-i-o/)
- 「キャプチャ」を押し、次の再生開始から停止までを1テイクにする。長さ指定の場合は指定範囲の終端で終了する。受信時はブロック内のサンプル位置、チャンネル、イベントと利用可能なホスト位置を有界バッファに記録する。ループ折り返しとシークでテイクを分割し、停止時の未終了ノートを閉じる。容量超過は不完全なテイクとして明示する。音声処理スレッドの外で拍位置に変換し、元のタイミングとベロシティを保持する。ホストから音楽的位置を取得できないときは、手動BPMと取り込み開始を拍の原点に選べるようにする。
- 最初はノートオン／オフとベロシティ、チャンネルの往復を検証する。CC64を含むCC、ピッチベンド、アフタータッチは受信・書き出しの対応を項目ごとに示す。リアルタイム入力から歌詞は復元できない。MIDIファイルに歌詞メタイベントが入っている場合だけ、その時刻と文字列を歌詞割り当ての候補として提示する。Studio本体の現行SMF取り込みはコントローラーを省略するため、そのまま完全な往復には使えない。
- 通常はトラックのMIDIを子音源で鳴らす。キャプチャではその入力を記録しながらモニターする。「編集案を試聴」中は編集結果が子音源を鳴らす。自分が生成したノートをキャプチャ入力へ戻さない。反映後はトラック再生に戻し、元クリップと編集案の二重発音を防ぐ。プラグインの保存状態には作業中のフレーズ、使用したコード、子音源設定を含める。別曲でプリセットを開いても元クリップへの書き込み権限は引き継がない。

## コード進行と配置位置

Studioでは配置先の時刻に対応するグローバルコード進行を基準とする。クリップの先頭からの経過tickを配置先のスコアtickに変換し、小節途中のコード変更も拾う。分数コードのベース、明示されたボイシング、キー／スケールは別々に参照する。グローバルのコードやボイシングをアレンジャーから自動更新する動作は範囲外とする。

初期値は「原音を保持」。キャプチャ時の経過音、ブルーノート、コード境界をまたぐロングトーンを保つ。「配置先のコードに追従」を選んだ場合は、伴奏の和声音を元のコードに対する役割から置き換え、音域と前後の声部移動を考慮した候補を試聴する。例えば Cmaj7 の E–G–B を Dm7 の同じ役割に合わせる候補は F–A–C。持続音は初期値で維持し、変更される音だけを強調する。別の場所へドラッグしたときは、ドロップ先の進行でプレビューを更新してから追従結果を確定する。

外部DAWでは、コード参照元を「OSTFから読み込み」「手入力」「コード用MIDIを取り込み」から選ぶ。ホストが有効な現在コードを渡す場合は、再生中の観測値として時刻とともに収録できる。将来の全曲の進行が取得できるという前提は置かない。ノートから推定したコードは候補に留め、ユーザーが確定するまで原音を使う。SMFに書き出すのは、プラグイン側で試聴した音高。外部DAW内で配置後に進行が変わった場合は、更新した進行で再生成・再ドラッグする。[Steinberg VST3 ProcessContext](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/structSteinberg_1_1Vst_1_1ProcessContext.html)

## 実装順と受け入れ条件

| 段階 | 完了を判定する操作 |
|---|---|
| 1. 共通フレーズ | 固定4音のうち1音を変更し、子音源での試聴、SMFを読み戻したノート、Studioへ新規ドロップしたノートの音高・開始・長さ・ベロシティが一致する。子音源が見つからなくても書き出せる。 |
| 2. Studio内の往復 | 8小節のクリップを開き2音だけ編集。他のトラックを選んでから元クリップへ反映しても、対象と参照IDが保たれ、Undoで戻る。元クリップの削除、コード変更、同一提案の再送、保存失敗も試す。 |
| 3. 外部DAW | LiveとCubaseのWindows/macOS実機で、既存クリップを再生してキャプチャし、編集後のSMFを再配置して比較する。ループ、テンポ変更、途中停止、ホスト位置を取得できない場合を含める。 |
| 4. 和声追従 | 途中転調と小節途中のコード変更を含むフレーズを別位置へ置き、「原音を保持」と「コードに追従」を試聴比較する。元の進行と演奏が保持され、未知の区間と推定コードが区別できる。 |
